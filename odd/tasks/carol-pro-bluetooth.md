# Feature: carol-pro-bluetooth
Objective: extract the protocol from the two APKs, support the KZ Carol Pro ("CAROL PRO", the device PLAN.md calls Castor Pro) over Bluetooth on Android, Linux and Windows, and ship a responsive UI in the spirit of Nothing X. Generic JieLi detection first, Carol Pro as the first proven device.
Branch: `feat/carol-pro-bluetooth` (created before the first commit; no commits unless asked, AGENTS.md "Git"). Delivery: ask-on-risk (forecast above 400 lines, so the chain strategy is asked before the second commit). Runner: `fvm flutter test` for Dart code; capture analysis has no runner.
Prior evidence: the closed design ODD and the Phase 2 log (L1-L24) are archived outside the repo in `../re/archive/`; Engram topic `odd/phase2-discovery/tasks`.

## Specs
- S1 Static sources. Both APKs are decompiled with jadx outside the repo: "/home/fulanito/mydev/kz/KZAUDIO_1.0.8.apk" to `../re/kzaudio-jadx/` and "/home/fulanito/mydev/kz/KZ-Carol-Control.apk" to `../re/carol-control-jadx/`. They are references only: no code, assets or layouts are copied into the repo (AGENTS.md "Reverse engineering and legal"). Every claim cites path:line.
- S2 Auth. The earbuds open with an RCSP challenge and answer `02 70 61 73 73` ("pass") (Phase 2 L5). Both apps compute the answer in native code (`RcspAuth.getEncryptedAuthData`, `libjl_enc.so`). First prove live whether the Carol Pro accepts commands without auth. If auth is required, write a clean-room spec of the algorithm (from analysis of `libjl_enc.so`, outside the repo) and a pure-Dart implementation tested against live challenge/response pairs. No native library from either APK ships in our app.
- S3 Live confirmation. Each feature found in code (Phase 2 L24: EQ, key remap, find buds, work mode, volume) is confirmed with one `rcsp_probe.py sesion` action before it counts as proven. Safety: factory reset, reboot/shutdown, rename and OTA are never sent (Phase 2 S5).
- S4 Protocol docs. `docs/protocol/` holds the GATT map (0xAE00, AE01 write-no-response, AE02 notify), the frame format, the auth spec (S2), the capability matrix with four states (proven, seen in code, seen in the app only, unknown) and redacted fixtures: no MAC address, no device-unique auth key (AGENTS.md "Do not").
- S5 Protocol layer. A pure-Dart RCSP codec under `lib/data/protocol/` (frame build/parse, TLV, the S2 auth) with unit tests on the S4 fixtures (AGENTS.md rule 6).
- S6 Detection and transport. "poder detectar por el momento por bluetooth", "porque el principal motivo es que cualquiera le pueda sacar partido realmente". Transport (L10): "SPP en todo": RFCOMM/SPP (0x1101) on Android, Linux and Windows; BLE is deferred (iOS/macOS later). Detection lists the earbuds already paired with the OS and keeps JieLi RCSP devices generically, never by model name (AGENTS.md rule 3). Scope (L10): "Hasta handshake real": detect, connect, live auth and a battery read on Linux; UI wiring stays in T8. The SPP package version is verified on pub.dev before it is added (AGENTS.md "Toolchain").
- S7 Carol Pro support. "en primera para el soporte para los KZ Carol pro": connect, auth, connection state, left/right battery (case = null, Phase 2 L17/L20) and every S3-proven capability, on Android and Linux; Windows is built and smoke-tested.
- S8 Responsive UI. "nuestra referencia es hacerla como esta aplicación:https://apps.apple.com/us/app/nothing-x/id1568033706 este es nuestro objetivo que la app sea responsive para que se ve abien en android como en desktop". Design ideas only, nothing copied; built on the existing design system (WidgetsApp, AGENTS.md rule 9); works with `FakeEarbudsAdapter` first (rule 7).
- S9 Out of scope: "después le metemos caña a los dispositivos con USB C, por el momento bluetooth". No USB/DAC code (AGENTS.md "Do not").
